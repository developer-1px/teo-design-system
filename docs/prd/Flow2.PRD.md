# Flow2 데이터 파이프라인 어댑터 PRD
상태: DRAFT (REVIEW REQUIRED)

## 1. 문제 정의
- **컨텍스트**: 개발자는 소스 데이터를 타겟 규격에 맞게 변환하는 자바스크립트 코드를 작성함.
- **통증 지점**: 
    1. 4열 배치(Source-Code-Result-Target)는 가로 폭이 좁아 실제 대량의 결과 테이블을 확인하기 어려움.
    2. 결과 확인을 위해 모달을 띄우는 행위는 '코드 수정-결과 확인'의 빠른 피드백 루프를 단절시킴.
    3. 개발자는 `Tab` 키를 코드 들여쓰기에 사용해야 하므로, 게임과 같은 `Tab` 기반 UI를 그대로 쓸 수 없음.

## 2. 주요 기능: "Scoreboard View" (Scoreboard Pattern)
개발자가 코딩 중 **맥락을 잃지 않고 즉시 대형 결과 보고서를 엿보고(Peek) 다시 복귀**하는 인터랙션을 제공합니다.

### 2.1. 핵심 매커니즘: Ephemeral Result Overlay
- **트리거**: `` ` `` (Backtick / Tilde `~`) 키 (또는 개발자가 지정한 전용 토글 키).
- **동작**:
    - 키를 **누르고 있는 동안(Hold)**: 화면 전체에 반투명한 대형 결과 테이블이 오버레이 시스템으로 등장.
    - 키를 **떼면(Release)**: 즉시 사라지며 원래의 에디터 커서 위치로 복귀.
- **장점**: 별도의 화면 전환이나 마우스 클릭 없이 '눈'만 굴려 결과를 확인하고 바로 다음 코드를 작성할 수 있음.

## 3. 사용자 흐름 (Happy & Unhappy Paths)

### 3.1. Happy Path: 수정-확인 루프
1. `FlowPage2` 진입 시 전체 화면의 80%가 코드 에디터로 노출됨.
2. 개발자가 `input.payload.price * 1.1` 로 코드를 수정함.
3. `` ` `` 키를 누름 -> 즉시 대형 결과 테이블이 전면에 나타나 가격이 올랐는지 확인.
4. 키를 뗌 -> 다시 에디터로 복귀하여 다음 필드(stock) 작업 시작.

### 3.2. Unhappy Path: 키 충돌 및 성능
- **키 충돌**: 에디터 내에서 실제 백틱(`` ` ``) 문자를 입력해야 할 경우 (Template Literals 등).
    - **해결책**: 에디터 포커스 상태에서는 `Option + ~` 또는 특정 특수키 조합으로 우회하거나, 에디터 영역 외(Gutter 등)에서 트리거되도록 함.
- **성능**: 데이터가 수만 건일 경우 오버레이 인스턴스 생성 시 지연 발생.
    - **해결책**: 가상 스크롤(Virtual Scroll) 및 렌더링 최적화 필수.

## 4. UI/UX 상태 정의

### 4.1. 전장 모드 (Battle Mode)
- **에디터**: 최대화.
- **사이드바**: 소스/타겟 스키마 정보가 최소한의 영역(Slim Sidebar)으로 존재.

### 4.2. 점수판 모드 (Scoreboard Mode)
- **테이블**: 화면 중앙에 플로팅 카드 형태로 등장.
- **심미성**: 배경(에디터)이 블러(Blur) 처리되어 현재 결과물에만 집중하게 함.
- **정보**: 매핑 성공 여부, 유효성 검사 결과(Conform/Mismatch)를 컬럼 헤더에 강조.

## 5. 논리적 사양 및 동작 정의
- [x] `Tab` 키 대신 `` ` ``(백틱) 또는 `F2` 등의 비충돌 키 사용.
- [x] 결과가 100% 매핑되지 않아도 'Partial' 데이터를 그대로 노출 (디버깅 지원).
- [x] 에디터 내 에러 발생 시 오버레이 내에서도 에러 상태(Stack trace) 노출.
