# TableBuilderUX PRD
상태: [APPROVED]

## 1. 문제 정의
사용자가 데이터 스키마(테이블)를 시각적으로 정의할 수 있는 "노코드" 스타일의 인터페이스가 필요합니다. **범위 제한**: 본 PRD는 오직 **프론트엔드 인터랙션 및 시각적 디자인**에 집중합니다. 백엔드 통합, API 스키마 동기화 등은 범위 외입니다. 최종 결과물은 고해상도의 "컨셉 프로토타입" 또는 "스토리북 스타일"의 인터랙티브 쉘입니다.

## 2. 주요 사용자 흐름
1.  **테이블 보기**: 사용자는 헤더와 **자동 생성된 모킹 데이터**가 포함된 그리드를 봅니다.
2.  **컬럼 추가**: 사용자가 "+" 버튼 클릭 -> 이름 입력 -> 타입 선택 -> 그리드에 즉시 새 컬럼과 관련 모킹 데이터가 업데이트됩니다.
3.  **컬럼 속성 편집**: 사용자가 헤더 클릭 -> "컨텍스트 메뉴" 노출 -> 이름, 타입, 포맷(예: 통화) 변경.
4.  **컬럼 순서 변경**: 사용자가 헤더를 드래그하여 새 위치로 이동 -> UI가 재정렬 애니메이션을 수행합니다.

## 3. 데이터 모델 (프론트엔드 상태)
*상태는 데모 세션을 위해 일시적으로 유지되거나 localStorage에 저장됩니다.*

```typescript
type ColumnType = 'Text' | 'Number' | 'Date' | 'Status' | 'Select';

interface ColumnConfig {
    id: string;
    label: string;
    type: ColumnType;
    width: number; // 리사이징을 위한 픽셀 값
    description?: string; // 툴팁용
    options?: string[]; // Status/Select 타입을 위한 옵션들
}
```

## 4. UI/UX 상태 및 인터랙션 전략

### 4.1. "근접 노출" 패턴 (Notion 방식)
- **기본 상태(Passive)**: 테이블은 최종적으로 서빙될 형태를 반영합니다. 아이콘, UI 크롬, 핸들 등이 보이지 않는 순수한 데이터 시각화 상태입니다.
- **근접/호버 상태(Proximity/Hover)**: 마우스가 헤더 영역에 진입하면:
    - **헤더 아이콘**: 페이드 인 (Opacity 0 -> 1).
    - **액션 버튼 (More/Plus 등)**: 모습을 드러냅니다.
    - **리사이즈 핸들**: 컬럼 오른쪽 경계에 미세한 1px 구분선이 나타납니다.
    - **컬럼 추가 (+)**: 마지막 컬럼 우측에 아주 작고 간결한 형태의 "+" 버튼이 노출됩니다. (디자인을 해치지 않는 최소한의 티내기)
- **활성 상태(Active)**: 컬럼이 편집되거나 이동 중일 때 시각적 무게감이 강조됩니다 (파란색 테두리/그림자).

### 4.2. 오버레이 및 컨텍스트 메뉴
- **메커니즘**: 드롭다운 오버레이.
- **UX 규칙**: 기존 그리드를 흔들거나 방해해서는 안 됩니다. 콘텐츠 위에 엄격하게 떠 있어야 합니다.
- **밀도**: 단일 뷰 내비게이션. 타입을 변경하면 메뉴 내용이 즉시 교체되어 중첩 메뉴 없이 빠른 인터랙션을 유지합니다.

### 4.3. 드래그 앤 드롭 (DND) 시각 효과
- **고스트 투명도 (Ghost Opacity)**: 드래그 중인 요소에 `0.3` 적용.
- **플레이스홀더**: 컬럼이 착륙할 위치에 "면(Surface)" 형태의 하이라이트를 적용합니다.

### 4.4. 정렬 및 타이포그래피
- **원칙**: 데이터 내용과 무관하게 **헤더는 항상 좌측 정렬**을 유지합니다.
- **데이터 정렬**: 특정 타입은 표준 관례를 따릅니다 (숫자 -> 우측, 텍스트 -> 좌측).

## 5. 비기능적 요구사항
- **시각적 완성도**: `vanilla-extract`를 사용한 테마 시스템 필수.
- **인터랙션**: 재정렬 및 메뉴 오픈 시 애니메이션 적용 (Framer Motion).
- **레이아웃**: 가로 스크롤을 지원하되, **고정 컬럼(Sticky)이나 벌크 액션 툴바 등은 포함하지 않습니다.** 오직 순수한 테이블 샌드박스 환경을 지향합니다.

## 6. 논리적 사양 및 동작 정의 (해결된 질문들)

### 6.1. 스마트 모킹 데이터 엔진
- **전략**: `faker.js`를 사용하여 새 컬럼을 자동으로 채웁니다.
- **휴리스틱**:
    - 라벨에 "Price"나 "Amount" 포함 -> 통화 데이터 생성.
    - 라벨에 "Email" 포함 -> 이메일 데이터 생성.
    - 일반적인 라벨 -> 타입에 따라 표준 텍스트나 랜덤 숫자 생성.

### 6.2. 타입 변환 및 데이터 반응성
- **규칙**: 컬럼 타입이 변경되면(예: Text -> Number), 시스템은 **기존 데이터를 버리고** 새 타입에 맞는 **데이터를 재생성**합니다.
- **목표**: 항상 "고해상도" 외관을 유지합니다. 숫자 필드에 "ABC"가 보이는 등의 데이터 미스매치를 허용하지 않습니다.

### 6.3. 지속성 (Persistence)
- **메커니즘**: `localStorage`.
- **범위**: `columns`, `tableName`, 그리고 모킹 데이터의 시드를 저장하여 새로고침 후에도 유지되도록 합니다.

### 6.4 상태(Status) 설정
- **기본값**: `faker`를 사용하여 "Active", "Pending" 등의 랜덤 태그 자동 생성.
- **커스텀**: 사용자는 컨텍스트 메뉴를 통해 고유한 태그를 추가/삭제할 수 있습니다.

### 6.5. 실행 취소 (Undo) 메커니즘
- **삭제 보호**: 컬럼 삭제 시 즉시 데이터가 영구 삭제되는 것이 아니라, UI 하단에 **"컬럼이 삭제되었습니다 (Undo)"** 버튼이 포함된 토스트가 노출됩니다.
- **유효 기간**: 약 5초간 Undo가 가능하며, 이 기간이 지나거나 다른 파괴적 액션이 발생하면 상태가 완전히 확정됩니다.


### 6.6. 향후 확장 아이디어 (Keep)
- **실데이터 프리뷰**: 향후 실제 API 연동 시, `faker` 데이터 대신 실제 데이터 샘플을 활용하여 미리보기를 제공하는 시각적 장치 고려. (현재 단계선 구현 제외)
